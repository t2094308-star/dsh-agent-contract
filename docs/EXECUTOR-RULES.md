# EXECUTOR-RULES.md — 执行方（dsh 主代理 / 子智能体）行为准则

> **每次动手前先读本文件**。它不替代单据（`FIX.md` / `REVIEW-*.md` / `MIGRATE.md` / `M2.5.md` / `M4.md`），而是规定"怎么动手"。
> 一句话总纲：**你是执行方，不是项目所有者——先看清，再动手，留后路，留痕迹。**

## 1. 动手前三件事

1. **核对版本与基线**：运行版本 vs 工作树 `package.json`；项目仓库 `git status --short`（`D:\Blockdustry\仓库` 是 git 仓库）——先知道"现在是什么状态"
2. **先 dryRun**：任何写操作先跑干跑，把"将做什么"列出来
3. **声明范围**：明确"这次会碰哪些路径"，范围之外的**一律不碰**

## 2. 写操作四禁（踩过的坑，别再踩）

1. **禁不带备份的覆盖**：写入会改写/覆盖**既有文件**前，先复制到 `<项目根>/.agent-contract/backups/<时间戳>/<相对路径>`；备份失败 → **中止该文件的操作**
2. **禁整篇重写既有索引/README**：必须"**保留人工段落 + 在指定区块内增量合并**"；dryRun 显示 `+N/-M`，**删除行数 > 0 时必须列出被删内容**再执行
3. **禁用"第一个分隔符"猜标识**：任务号/前缀提取一律 `startsWith(knownPrefix)` 精确剥离；改名必须幂等（同名 → 跳过）
4. **禁顺手改单据外的东西**：发现问题**只报告并立单**，不顺手修；审查 ≠ 修改

## 3. 项目不是沙箱

对 `D:\Blockdustry` 的任何写入都是**生产改动**：
- 事前声明影响面；事后给**可核验证据**（sha256 前 12 位 / 条目数 / 绝对路径清单）
- 「附：一级/二级文档」这类**规范要求的段落**，补比删安全（设计要求必须回贴绝对路径）
- 派生物（索引/快照/派生态核心数据库）**必须头部自述"派生物·可重建"**，且**不得**写进既有文档所在的类目录

## 4. 留痕与回滚

- 改动写入文件头（`librarianTouchedAt` / `librarianChanges`）+ 核心数据库 changelog **追加**；**绝不改写历史日志行**
- 回滚：**外科手术式**——只回滚被改错的项（名/引用），**保留同轮的正常产出**
- **做不到字节级还原时：如实说明 + 交人裁决**，不要赌一个"看起来对"的版本

## 5. 报告纪律

- 每条结论带 **命令 + ≤20 行原始输出 + 文件绝对路径**；"看代码觉得没问题"不算证据
- **套件结果以 `exit code` 为准**：只 `tail -3` 看尾部会**把失败淹掉**（实测：`tail -3` 显示 `Node.js v22.23.0` + `cleaned:` 像是跑完了，实际 `exit=1` 断在中间）。必须看 **完整尾部（≥20 行）+ 退出码**，并显式写出 `exit=0/1` 与断言块数
- **报告"全绿"必须带版本号与时间**：口头"75 块全绿"若与当前工作树不符（实测 0.2.8 上 `exit=1`），等于给了假信号
- 不明确 → 写 `未核验（原因）`；**不许猜、不许代答**（C 组类主观项只记录用户答复）
- **数字口径不一致时两个都写并说明**（例：`split("\n")` 报 564→580 而 `Get-Content` 实测 563→579，差的是尾换行）——不要挑一个写，否则会被当成矛盾
- **结构变化与内容变化分开交代**（例：新增 4 行结构行 + 原 6 行内容一字未改 → 才能得出"删行 0"的结论）
- 版本漂移必须写明（运行版 vs 工作树）；干跑结果不得当作已落盘证据

## 6. 收尾

- 夹具/临时产物**可还原或清单化**，报告末尾交代"留下了什么、清掉了什么"
- 结论先行：先给判定（通过/失败/未核验），再给逐条证据
