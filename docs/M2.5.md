## 交付物 1 · `doc_search`（检索 L0）

**定位**：先缩小范围、给"指路"结果，**不替代 `grep`**（L1/L2 由宿主原生工具负责）。

**涉及文件**：新增 `src/search/doc_search.js`；在 `src/tools.js` 注册工具 `doc_search`

**入参**：`query`（关键词或正则，必填）· `taskId?` · `role?` · `tier?` · `limit?`（默认 10）

**出参**：
```js
{
  results: [{
    path,            // 绝对路径
    tier, taskId, chars,
    keywords,        // 来自 front-matter
    snippets: [{ line, text }],   // 命中行（≤3 条/文档）
    score,           // 排序分（见下）
    hitReason,       // 命中原因：只允许实词（复用 FIX-2 的泛词表）
  }],
  suggest: ['<path>#结论', '<path>#依据'],   // 建议 read 哪几节（readHints）
  scanned, filtered,   // 台账过滤统计，便于验证"先过滤再匹配"
}
```

**实现要求**：
1. **先 L0 过滤**：从台账 `docs` 表按 `project` 收窄 → 再按 `taskId`/`role`/`tier` 过滤 → **只对候选**做轻量匹配（不得全库扫描）
2. **排序**：`keywords` 精确命中 > 标题命中 > 正文命中；同分按 `updatedAt` 新者优先；`score` 可解释（在 `hitReason` 里能看出来）
3. **泛词**：复用 FIX-2 的停用词表；泛词**不得**进入 `hitReason`，也不得作为召回依据
4. **`suggest`**：从命中文档的固定小节（`## 结论` / `## 依据` / `## 风险与待确认` / `## 下一步`）里挑最相关 1~2 个，输出 `路径#小节名`
5. **演进预留**：文档数超阈值（约定 1500）或需要权重/模糊检索时，内部切 FTS 实现，**工具签名不变**（M2.5 只需留接口与注释）

**验收（补测试）**：
- 建 fixture：若干净档 + 1 篇命中档 + 1 篇泛词档；用实词检索 → 只召回命中档，`hitReason` 无泛词；用纯泛词检索 → **零召回**
- 断言"先过滤后匹配"：`filtered` 明显小于 `scanned`，且未过滤掉含该实词的候选
- `suggest` 输出形如 `<绝对路径>#结论`

## 交付物 2 · 检索阶梯写进角色卡

**涉及文件**：`src/contract/roles.js`（各角色卡的"检索纪律"段）

**要求**：每个角色的卡里写明按成本递增的检索顺序（文案口径见 DESIGN §5.5）：
```
L0 doc_search（台账过滤，先缩小范围）
L1 glob（按命名规范找文件：<任务号>_*_L1|L2|L3.md）
L2 grep（全文正则，定位 文件+行号）
L3 read（按 readHints 只读指定小节）
L4 session_search（跨会话检索："上次同类任务怎么做的"）
```
**验收（补测试）**：断言每个角色的 `persona`/卡文案包含 `doc_search`、`glob`、`grep`、`read`、`session_search` 五个关键词，且顺序与上表一致。
