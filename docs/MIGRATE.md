## 1. 迁移映射（**只移动，不改名**）

> 原则：**只改目录，不改文件名** —— 项目里大量文档互相引用旧路径，改名会让引用成片断裂；改名/拆分留到后续规范化任务单独做。

| 现位置（`仓库/docs/` 根） | 迁往 |
|---|---|
| `^研究-*.md`（约 15 篇） | `仓库/docs/研究/` |
| `研究-渲染与模型坑.md` | `仓库/docs/研究/` |
| `^修改-*.md` | `仓库/docs/修改/` |
| `核心数据库.md` | `仓库/docs/核心数据库/核心数据库.md` |
| `^单位工厂与单位.md`、`^电力系统.md`、`传送带上下坡.md` | **归属需判断**：内容属"研究/机制考证"→ `研究/`；属"改动记录"→ `修改/`；判不准 → 进 `needs_librarian` 清单并**保持原位**，不要猜 |

**判不准就留在原地**——这是本条的核心纪律：宁可待办，不要猜错。

---

## 2. 迁移后必须做的三件事

1. **更新引用**：全仓库检索旧路径（`仓库/docs/^研究-…` 等），把引用改到新路径。
   - 范围：`仓库/docs/**`、`任务/*.md`、`仓库/src/**`（注释里可能有）、`待办.md`
   - 验收：用旧路径检索 **零命中**
2. **留痕**：每篇被移动的档，在 front-matter 追加 `librarianTouchedAt` 与 `librarianChanges: ["移动到 仓库/docs/研究/"]`；无 front-matter 的档先补头部再记（补头部规则见 `FIX-3` 与 `doc_emit` 的六字段）
   - **正文一个字都不许改**
3. **核心数据库 changelog**：追加一条 `[目录规范化] 迁移 N 篇：研究 x / 修改 y / 核心数据库 z`（追加，不覆盖既有内容）

---

## 3. 验收标准（逐条可查）

- `仓库/docs/` 根目录下 **`.md` 数为 0**（只剩目录）
- 六个目录各就位：`研究/ 坑/ 修改/ 核心数据库/ 子agent/ archive/`
- 用旧路径全仓检索 → **零命中**
- 被迁移文档的正文 sha256 **与迁移前一致**（只动头部）
- `doc_misfiled` 审计项对 docs 根 → **零报警**
- 判不准的档已列入 `needs_librarian` 清单（数量与文件名明确写出），且**仍留在原位**

---

## 4. 禁止事项

- **不得改名**（本单只做目录迁移）
- **不得删除任何文件**（迁移=移动）
- 不得改文档正文；不得改 `仓库/src/**` 源码；不得动 `子agent/` 内的产出档
- 不得为了让 `doc_misfiled` 归零而把判不准的档"随便塞进某一类"
- 迁移完成后**不要**自行移除配置里的过渡源（`仓库/docs`）——那一步等主代理确认迁移验收通过后单独做
