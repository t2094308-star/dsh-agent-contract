## 0. 版本闸门（**动态口径**）

- 期望值 = **核验时现场读** `D:\DSH插件\dsh-agent-contract\package.json` 的 `version`（当前 **0.2.3**）。**不得**沿用历史基准号（实现方会连续跳档）。
- 同时比对 `contract_status` 打印的 `插件版本` 与 `已注册工具（18）` 清单。
- 不一致 → 标「**未核验（版本漂移）**」并**停止运行时部分**。排查顺序：① 完整重启（托盘 Quit ≠ 关窗口）② 是否有第二个 app 实例在跑 ③ profile 的 link 是否存活 ④ 必要时重新 `dsh plugin --profile desktop add link:D:\DSH插件\dsh-agent-contract`。
- 注意：**闸门只挡运行时核验，不挡代码改动**。

## A 组 · 机器核验

| # | 项 | 判据 |
|---|---|---|
| A1 | canonical 套件 | `node scripts/verify-node.mjs` 全绿；报**实际项数**与新增项归属 |
| A2 | M3 专项断言可检索 | 套件里能检索到 `FIX-6`/`FIX-7`/`FIX-11`/`FIX-12`/`FIX-13`/`FIX-15`/`FIX-16` 相关断言名 |
| A3 | **fail-open 回归位** | 空/不完整工具目录下**不得剔除任何声明名**（`allow === 声明名`，终端名经平台解析）；win32 → 仅 `pwsh`；非 win32 → 仅 `bash` |
| A4 | **血缘/过滤回归位** | `items 不含 scope` → `roots ≥ 1`；`settled continuable` 默认**可见**；`one-shot + completed` 默认**隐藏**；`unknown` 默认**可见** |
| A5 | **remote 访问回归位** | `props.ctx` 无 `remote.workspaceFiles`、注入 ctx 有 → **仍能读到快照**；且「读血缘失败」与「读快照失败」的 reason 文案**不同** |
| A6 | 空态三分类 | `failed`（含“remote 未注入”原因）/ `sourceEmpty`（宿主未返回会话列表）/ `filteredOut`（过滤后无可见节点）三类文案**互不相同** |
| A7 | host 侧快照 | `<项目根>\.agent-contract\panel.json` 含 `schemaVersion`/`generatedAt`/`members`/`audit`/`counts`；徽章为**真值**（不是一排 unknown） |
| A8 | 委派回执可见性 | `warnings` 非空时，回执 `render` 输出含「警告：」且逐条列出 |

## B 组 · 运行时核验（版本闸门通过后做）

| # | 项 | 做法与判据 |
|---|---|---|
| B1 | 版本与工具面 | `contract_status` 首两行：版本 == 工作树版本；`已注册工具（18）` 清单逐字一致 |
| B2 | **工具实质验收**（重点） | 派「实现者（后台）」→ 要求它**自报当前可调用工具清单**，并在临时目录实测 `read` / `write` / `pwsh` 各一次。判据：**不得只剩** `doc_emit`/`progress_upsert`/`subagent` |
| B3 | **快照链路** | 触发 `audit_scan`（或 `ledger_rebuild`）→ `panel.json` mtime 刷新、内容正确；**回到面板**看徽章**不再是“待接”**（三档/进度应为真值，预算/异源可为 unknown） |
| B4 | 面板数据 | 能出树（成员 ≥ 1）；**成员总数 − 可见节点数**应等于"被默认隐藏的已完成一次性"数量 |
| B5 | **两个同名 reviewer 节点** | 核对两者 `sessionId`：**不同** = 两次派单（正常）；**相同** = 去重缺陷，按 FIX 条目格式记缺陷 |
| B6 | 跳转通道 | 若能在无 GUI 情况下触发（或从源码确认走 `onSubagentJump`）则记录；否则标「需用户确认」 |

## 报告格式

```
0  版本闸门：工作树版本 = ? | contract_status 版本 = ? | 工具数 = ? → 通过/漂移（漂移则停止 B 组）
A  逐条：通过/失败 + 命令 + 原始输出(≤20 行)
B  逐条：通过/失败/未核验(原因) + 证据（命令与输出、文件绝对路径）
C  用户答复原样记录 + 标注「由用户肉眼确认」
新缺陷：现象 / 涉及文件 / 修法 / 验收断言 / 最小复现
汇总：A 通过率 · B 通过/未核验 · C 已确认数 · 新缺陷数
```
